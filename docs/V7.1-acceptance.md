# V7.1 Acceptance Checklist

V7.1.6 is the V7.1 release candidate for the stable multi-mode release. Use this checklist for final manual validation and PR review.

## 1. Version Information

- Version: V7.1.6
- Goal: V7.1 stable release candidate
- Players: 2-8
- Client: mobile browser first, desktop supported
- Server: server-authoritative state machine
- Playable modes: Classic, Quick, Escalation, Shared Revolver, Free Challenge, Party
- Custom: planned / disabled

## 2. Classic

### Room Flow

- Create a room.
- Join a room from another browser/client.
- Host changes max players.
- Players ready and unready.
- Host starts the match after requirements are met.
- A player leaves the room.
- A player returns to lobby from the room/game flow.
- Host starts another match from the room after a completed game.
- Host changes mode before starting another match and all players re-ready.

### Base Match

- Current player can play 1 card.
- Current player can play 2 cards.
- Current player can play 3 cards.
- Non-current player cannot play cards.
- Client cannot play a card index that is not in its hand.
- The previous play can be challenged after cards are played.
- Honest and bluff verdicts are correct.
- Joker is treated as wild in normal rounds.

### Challenge And Reveal

Expected phase order:

```text
CHALLENGE_CALLOUT
-> REVEAL
-> VERDICT
-> PUNISHMENT_INTRO
-> PUNISHMENT_TRIGGER
-> PUNISHMENT_RESULT
-> ROUND_END
```

Checks:

- Reveal flips cards one by one.
- A card that has flipped to front never visually flips back.
- The finalHold after the last card remains front-facing.
- VERDICT uses static front-facing public cards.
- PUNISHMENT_INTRO, PUNISHMENT_TRIGGER, PUNISHMENT_RESULT, and ROUND_END keep the same public cards face-up.
- New ROUND_START clears the previous round's public cards.

## 3. Quick

- Turn duration is 7 seconds.
- Timeout handling advances the game.
- Automatic timeout behavior follows server rules.
- Quick does not change honest/bluff/Joker judgment.
- Challenge flow works.
- Punishment flow works.
- Reconnect restores remaining time and current phase without resetting authority.

## 4. Escalation

Core rule:

```text
minimum play count for the next play = previous play count
```

Checks:

- First play allows 1-3 cards.
- If the previous play used 2 cards, the next play requires at least 2 cards.
- If the previous play used 3 cards, the next play requires at least 3 cards.
- A player with too few cards for `minimumPlayCount` must challenge.
- Timeout automatic behavior respects `minimumPlayCount`.
- UI shows the current minimum play requirement.
- Reconnect preserves `minimumPlayCount`.

## 5. Shared Revolver

- The whole table shares one revolver.
- Every client sees the same public shared revolver state:

```text
currentChamber
shotsTaken
```

- Clients never receive `bulletPosition`.
- A dry shot advances the shared revolver for the next punishment.
- A hit eliminates the punished player and reloads the shared revolver.
- Elimination state is correct.
- Reconnect restores shared revolver state.
- Shared Revolver HUD shows the shared dry-shot pressure consistently.

## 6. Free Challenge

Core flow:

```text
Player A plays cards
-> 3 second CHALLENGE_WINDOW opens
-> all other alive players may race to challenge
-> server accepts only the first valid request
```

Automated real Socket.IO coverage exists in `apps/server/tests/multiplayer.test.ts` using multiple real clients racing to challenge.

Checks:

- With 4-5 real Socket.IO clients, at most one challenge succeeds.
- Every client converges on the same challenger.
- Losing challenge attempts receive authoritative errors.
- A player cannot challenge themself.
- Eliminated players cannot challenge.
- Requests after the window closes are rejected.
- If nobody challenges, the game advances to the next player.
- Disconnect/reconnect does not reset the challenge window.
- `phaseEndsAt` does not reset during reconnect.

## 7. Party

Party randomly selects one event each round. Party must not stack with Shared Revolver, Free Challenge, or Escalation, and Party's own event pool must not be disabled by the older V7 tavern event switch.

### BLACKOUT

- Other players' hand counts are hidden.
- The current viewer's own hand count remains visible.
- Counts restore after the event ends.

### DRUNKEN

- Turn direction reverses.
- `nextAlivePlayer` follows the reversed direction.
- Reconnect restores the reversed direction.

### RAPID_NIGHT

- Turn duration is shortened.
- UI countdown matches server timing.
- Reconnect does not reset timing.

### DOUBLE_DANGER

- Punishment has at most 2 shots.
- If the first shot hits, punishment ends immediately.
- If the first shot is dry, the second shot is triggered.
- The second shot result is correct.
- UI can show:

```text
shot 1/2
shot 2/2
```

### NO_JOKER

- Joker is treated as bluff for the current round.
- Verdict logic and UI explanation match.
- Character abilities use the same truth rule as verdict:
  - WOLF safe-hand count does not count Joker as safe.
  - FOX hand hint does not count Joker as safe.
  - PANDA reveal memory reports Joker as bluff/non-target.
- Ability copy does not say "target card or Joker" during this event.

### FORCED_BET

- First play follows normal minimum count.
- Later plays require at least 2 cards.
- A player with too few cards must challenge.
- UI `minimumPlayCount` is correct.

## 8. V7.0 Extension Regression

### Items

- `itemsEnabled=false`: no items are assigned or shown.
- `itemsEnabled=true`: first-batch items work.
- Item usage respects current phase.
- Items do not override server-authoritative rules.

### Character Abilities

- `characterAbilitiesEnabled=false`: characters are visual identities only and UI does not imply active abilities.
- `characterAbilitiesEnabled=true`: existing lightweight abilities still work.

### Tavern Events

- Classic and Quick remain compatible with the older V7 tavern event switch.
- Special V7.1 modes do not incorrectly stack old V7 tavern events.

- Host can open every mode detail and select enabled modes from the detail panel.
- Non-host players can open every mode detail but cannot select modes.
- Custom mode detail can be viewed and remains unavailable for selection.
- No obvious overflow.
- Cinematic panel is centered during game.
- Reveal displays normally.
- Verdict is compact.
- No `verdict__seal` circle appears.
- Revolver stage is not sunk to the bottom.
- Punishment Result has no large empty panel.
- Round End has no empty oversized panel.

Checks:

- Mode detail panel is usable and does not overflow the viewport.

## 10. Disconnect And Reconnect

Validate reconnect during:

```text

CHALLENGE_WINDOW
REVEAL
```

- Player seat is restored.
- Current phase is restored.
- `phaseEndsAt` is not reset.
- Current turn does not change unexpectedly.
- Challenge state is restored.
- Shared Revolver state is restored.
- Party event is restored.
- `turnDirection` is restored.

## 13. Release Candidate Boundaries

Do not implement during RC:

- new modes
- new Party events
- new items
- new character abilities
- Custom Rules
- ranking
- stats
- chat
- achievements
- new animation systems
- `GameService` rewrite
- `CinematicLayer` rewrite
- Reveal redesign
- Lobby redesign

Architecture cleanup such as extracting mode differences into `mode-rules.ts` should be evaluated before V7.2, while keeping `GameService` as the single authoritative state machine.
